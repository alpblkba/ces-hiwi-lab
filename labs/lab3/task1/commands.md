# Commands — Lab 3.1 — Baseline synthesis

All commands run on the lab machine. Nothing here needs a board, a bitstream,
or X11 — Lab 3 stops at C synthesis.

## 1. Load the Xilinx environment

```bash
source /Software/xilinx/2022.2/Vitis_HLS/2022.2/settings64.sh
vitis_hls -version | head -n 2
```

The version must read **2022.2**.

## 2. Create a working directory

Keep tool projects out of the repository. Build here, and copy only the sources
and the reports back into the lab directory when you are done.

```bash
mkdir -p ~/vitis/lab3_task1
cd ~/vitis/lab3_task1
cp <repo>/labs/lab3/task1/src/matmul.h .
cp <repo>/labs/lab3/task1/src/matmul.cpp .
cp <repo>/labs/lab3/task1/src/matmul_tb.cpp .
```

## 3. Check the kernel compiles and is correct

Before involving the tool at all, the testbench can be built with an ordinary
compiler. This is fast and catches logic mistakes immediately.

```bash
g++ -O2 -std=c++11 \
    -I /Software/xilinx/2022.2/Vitis_HLS/2022.2/include \
    matmul.cpp matmul_tb.cpp -o matmul_test
./matmul_test
```

Expected output:

```text
matmul test passed (16x16, int8 operands, int32 accumulator)
```

## 4. Synthesize

Either use the GUI, or run the flow in batch with a Tcl script. Batch is
recommended here because Task 3.2 repeats it many times.

```bash
cat > run_hls.tcl <<'EOF'
open_project -reset matmul_prj
set_top matmul
add_files matmul.cpp
add_files -tb matmul_tb.cpp
open_solution -reset "solution1" -flow_target vivado
set_part {xc7z007sclg400-1}
create_clock -period 10 -name default
csim_design
csynth_design
exit
EOF

vitis_hls -f run_hls.tcl
```

For the GUI instead:

```bash
vitis_hls &
```

Top function `matmul`, part `xc7z007sclg400-1`, clock period `10` ns, testbench
added on the separate test bench page.

## 5. Read the results

```bash
REPORT=matmul_prj/solution1/syn/report/matmul_csynth.rpt

# latency and initiation interval
grep -A6 "Latency (cycles)" $REPORT | head -8

# resource totals
sed -n '/Utilization Estimates/,/Interface/p' $REPORT \
    | grep -E "^\|(Total|Available|Utilization)"

# per-loop detail - the most useful table in the whole report
sed -n '/Detail/,/Utilization/p' $REPORT | head -30
```

## 6. Keep the results

```bash
mkdir -p <repo>/labs/lab3/task1/hls
cp $REPORT <repo>/labs/lab3/task1/hls/
```

Copy the report, not the project directory. The build tree is large, machine
specific, and regenerated by re-running the flow.

## Troubleshooting

**Latency shows `?`**
The loop bounds are not compile-time constants. Check that `N` in `matmul.h` is
a `#define` and that no size is passed in as an argument.

**C simulation fails**
Run the plain `g++` build from step 3 and debug there. It is the same code, and
the error messages are far easier to read.

**DSP usage is much higher than expected**
Check the data types in `matmul.h`. If `data_t` is `int` rather than
`ap_int<8>`, the design will use roughly five times more DSP slices.

**`vitis_hls: command not found`**
The environment in step 1 was not sourced, or it was sourced in a different
shell than the one running the command.
